Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a stateless FastAPI service that serves in-memory mock data loaded from JSON files. There is no database.

System Architecture

Three tiers, all running locally. The browser loads the SPA from Vite and calls the API directly over HTTP; the API reads only from process memory.

Data Flow

Example: a user changes the Warehouse filter on the Dashboard.

FilterBarUser selects a value; it writes to a shared ref in useFilters.
Singleton stateRefs are module-level, so every view sees the same filter values.
View watcherView watches the refs and calls getCurrentFilters().
api.jsDrops 'all' values and builds the query string.
FastAPI routeapply_filters() then filter_by_month() over in-memory lists.
PydanticValidates and serializes the response to JSON.
Computed propsRaw data lands in refs; KPIs and charts are derived via computed().

Rules worth knowing

  • The value 'all' means "no filter" on both the client and the server.
  • Inventory has no time dimension, so month is ignored for it.
  • Quarters are expanded to three months using QUARTER_MAP (2025 only).
  • Month matching is a substring check against order_date.
  • Demand, backlog, spending and reports endpoints take no filters.

Observations

Missing backend endpoints. App.vue calls api.getTasks / createTask / deleteTask / toggleTask (/api/tasks), but server/main.py doesn't define any /api/tasks routes, so these requests return 404. api.js also defines purchase-order POST/GET helpers that have no matching server route.
Unrouted view. views/Backlog.vue exists but isn't registered in the router. Backlog data is shown on the Dashboard instead.
Read-only, stateless data. Data is loaded once at import time, and any change is lost on restart. Filtering is a linear scan, which is fine at demo scale.
Hardcoded API URL. http://localhost:8001/api is set in api.js and repeated in Reports.vue, with no environment-based config.
